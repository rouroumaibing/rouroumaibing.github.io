二、架构图（一律纯文本输出，不依赖 Mermaid/PlantUML 渲染插件）

> 通用规范：架构图统一用 ```text 围栏绘制，框/箭头用 ┌─┐│▼▶ 等字符即可；凡涉及源码调用链，每个环节都要标注 `文件:行号`（例：`src/main.go:20`）。源码不在手边时，须注明依据（官方文档 / 设计文档），不得臆造路径。下面的示例均为占位，撰写时替换成目标软件的真实名称与文件。

2.1 代码逻辑图（从代码入口到具体文件/函数，带 file:line 标注）

沿程序真实调用链，自入口逐节点串到落地动作；每节点一行，右侧标 `文件:行号` + 本步职责；用 └─▶ / ├─ 表达顺序与分支。

```text
① 程序入口 main()                    <入口文件>:行号
   └─▶ 初始化框架 / 加载配置          <文件>:行号
        └─▶ 注册监听 / 启动循环        <文件>:行号
             ├─▶ 处理分支 A           <文件>:行号
             └─▶ 处理分支 B           <文件>:行号
   ...（以此类推，直到最终落地动作，如「worker 处理请求 / 写入存储」）
```

2.2 分层架构图（Layered Architecture Diagram，纯文本框）

自底向上分层（基础设施层 → 核心服务层 → 应用/展示层），每层用 ┌─┐ 框包裹模块，层间用 │ 依赖 ▼ 连接；直接输出 ```text，不要 Mermaid/PlantUML。

```text
┌──────────────────────────────┐
│ ① 应用/展示层                 │
│   - <模块A> / <模块B>          │
└──────────────┬───────────────┘
               │ 依赖 ▼
┌──────────────────────────────┐
│ ② 核心服务层                  │
│   - <模块C> / <模块D>          │
└──────────────┬───────────────┘
               │ 依赖 ▼
┌──────────────────────────────┐
│ ③ 基础设施层                  │
│   - <模块E> / <存储/网络>      │
└──────────────────────────────┘
```

把一组相关资源（如多个 YAML/配置对象）按字段绑定串成树状/链路图，边上注绑定字段（用 `<关联字段X>` 占位），并附「字段绑定速查表」。用 ```text 输出。

